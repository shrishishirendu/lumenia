CORE CONCEPTS

Ops Agent is NOT marketing. It optimizes “calm reliability” and “learning uptime,” not revenue.

────────────────────────────────────────
AUTONOMY LEVELS (REQUIRED)
────────────────────────────────────────
LEVEL 0 — OBSERVE ONLY
- Agent can: monitor, detect, draft incident/alert entries, recommend mitigations
- Agent cannot: apply mitigations, change policies, escalate automatically

LEVEL 1 — ASSISTED EXECUTION
- Agent can: notify human, generate “Apply mitigation” buttons, create handoff packs
- Human must click to apply mitigations and to assign human tutor

LEVEL 2 — SEMI-AUTONOMOUS
- Agent can: auto-apply SAFE mitigations within guardrails (pre-approved list)
- Must notify human for each action taken
- Cannot change policies or trigger major state changes

LEVEL 3 — AUTONOMOUS WITH GUARDRAILS
- Agent can: apply mitigations, throttle load, open/close incidents, trigger handoffs
- Must: log every action, show reasoning + confidence, alert human on thresholds
- Must: auto-downshift autonomy on repeated low-confidence or policy breach

Autonomy level must be:
- Settable by human in UI
- Logged with timestamp and actor
- Show “WILL / WILL NOT” for the current level

────────────────────────────────────────
OPS AGENT LOGIC (WORKFLOW-FIRST)
────────────────────────────────────────
Implement an Ops “Detector + Recommender” engine:

1) Detect anomalies:
- if p95ResponseMs > slaTargets.p95ResponseMs → create latency alert
- if errorRatePct > maxErrorRatePct → create errors alert
- if session success < minSessionSuccessPct → session failures alert
- if tutorUtilizationPct > maxTutorUtilizationPct → capacity overload alert
- if earlyExitRatePct or stuck/hints exceed thresholds → quality drop alert

2) For each alert, propose mitigations from the catalog with:
- reasoning
- alternatives considered
- confidence score

3) Apply mitigations based on autonomy:
- Level 0: recommend only
- Level 1: show “Apply” button; human clicks
- Level 2: auto-apply SAFE mitigations only; notify human
- Level 3: auto-apply safe + major actions per policy; request approval for major if configured

4) Human handoff:
When learning-quality thresholds are breached for a student/session (mock a studentId), create a HumanHandoffCase with a context pack and add to the Handoff Queue.
At high autonomy, it can auto-create and notify; assignment always human unless policy permits.
