You are Replit Agent working inside the EXISTING tutoring platform codebase. We have login issues and role/page overlaps between Student, Teacher/Tutor, Parent, and Admin. Fix authentication, authorization, navigation, logout, and role separation properly.

GOAL
Implement clean, secure, and user-friendly authentication + role-based access control (RBAC) so:
- Student, Parent, Tutor/Teacher, Admin experiences are clearly separated
- No page overlap or accidental access
- Logout is reliable everywhere
- Admin has a distinct login flow and a 360° view dashboard
- Navigation shows only what the logged-in role should see

DO NOT rebuild the whole app. Refactor the existing auth/layout structure.

────────────────────────────────────────
PROBLEMS TO SOLVE (CURRENT)
────────────────────────────────────────
1) Role overlap: Student pages, Parent pages, Teacher/Tutor pages, Admin pages bleed into each other.
2) Login issues: inconsistent session state, users appear logged in but see wrong nav/pages.
3) Missing/weak logout: no clear logout page and logout does not reliably clear session.
4) Admin login must be separate and stricter, and Admin needs a 360° view across the platform.

────────────────────────────────────────
TARGET DESIGN (WHAT TO BUILD)
────────────────────────────────────────

A) AUTHENTICATION
- Single auth system for all roles (shared underlying auth), but separate entry points:
  - /login (Student/Parent/Tutor)
  - /admin/login (Admin only)
- Support email+password (or existing provider) and session persistence.
- On login success, redirect based on role:
  - student -> /student
  - parent  -> /parent
  - tutor   -> /tutor
  - admin   -> /admin

B) AUTHORIZATION (RBAC)
Implement a role-based guard system:
Roles:
- "student"
- "parent"
- "tutor" (or "teacher")
- "admin"

Rules:
- Each route belongs to exactly one role namespace:
  - /student/*
  - /parent/*
  - /tutor/*
  - /admin/*
- A user can only access routes in their namespace (admin can access admin only).
- If unauthorized:
  - Redirect to a friendly /unauthorized page
  - Log the attempt (for dev console + optional admin audit log)

C) LAYOUT SEPARATION (NO OVERLAP)
- Create a dedicated layout per role:
  - StudentLayout: “My Classroom” as primary, no admin links
  - ParentLayout: “Parent Portal” primary, progress + communications
  - TutorLayout: student roster + session queue + notes
  - AdminLayout: 360° dashboard + agents + settings
- Remove shared top nav that mixes roles. Role decides the entire nav.

D) LOGOUT (MUST FIX)
- Add a visible “Logout” in every role layout, same position (top right).
- Implement a /logout route that:
  - clears session tokens/cookies/localStorage
  - invalidates server session (if present)
  - redirects to correct login page:
    - admin -> /admin/login
    - others -> /login
- After logout, user should not be able to go “Back” and see protected pages. Ensure route guards re-check auth.

E) ADMIN LOGIN: DIFFERENT AND STRICTER
Admin requirements:
- Admin users must be marked explicitly (role=admin).
- /admin/login only accepts admin accounts.
- If a non-admin tries /admin/login, show error: “Admin access only.”
Optional (recommended if easy):
- Add an extra admin security step:
  - OTP code / email code / “admin passcode” env var check (simple)
- Admin session timeout shorter than student/parent sessions (configurable).

F) ADMIN 360° VIEW (HIGH LEVEL)
Admin dashboard should show:
- Students count, active sessions, tutor utilization, recent signups
- Parent communications queue
- Agent dashboards (Marketing/Ops/etc)
- Search bar: search student name/id and jump to student 360 view

Student 360 view for Admin:
- Profile, grade, enrolled subjects
- Activity timeline (sessions, topics, quizzes)
- Learning signals (stuck events, handoffs)
- Parent notes + tutor notes
- Billing/subscription summary (if exists)

This 360° view is ADMIN-ONLY.
